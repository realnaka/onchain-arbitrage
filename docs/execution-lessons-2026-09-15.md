## 核心原则

**交易对象是套利组，不是孤立订单。开仓、平仓和完成报告必须核验两条腿及剩余敞口。**

本项目采用：流动性较差的链上现货先成交确认，再用流动性较好的合约对冲。外部手册中相反的顺序不能覆盖已经确定的项目策略。

两场所交易不是原子操作，无法保证真正同时成交或始终零敞口。中间单腿、部分成交、状态未知均属于需要跟踪和处置的风险状态，不能算完成。

## 过程、错误与纠正

| 过程／错误 | 原因与教训 | 下次必须做到 |
|---|---|---|
| 凭 ticker 推断合约存在或标的相同 | 名称相近不等于同一 underlying 或份额 | 从 API 元数据、发行方资料及链上 CA 建立审核映射；缺失即拒绝 |
| 先卖合约，未确认真实现货 | 把假设信号／假设库存带入实盘 | 正确链、正确代币的 receipt 成功且净到账确认后才提交合约 |
| approve 成功，swap 未完成 | 把授权中间步骤当作业务完成 | 单独记录 allowance、swap、receipt；失败进入恢复，禁止对冲 |
| 约 1.1703 枚现货对冲 1 张合约 | 金额接近不代表数量匹配，忽略乘数和步长 | 用审核后的份额比、实际成交量算残差，不能忽略取整余量 |
| “全部平仓”只平合约 | 按单腿理解任务，遗漏链上库存 | 建立组级双腿退出清单；两腿、挂单、pending、残差对账后才报完成 |
| DNS／超时后重复临时分析 | 没有先复用已验证线路 | 调用固定网络策略；读请求有限切换，未知写请求不重播 |
| 停止发单后未继续核对和报告 | 将停止交易误解为停止处理 | 继续有界只读核对；仍未知则明确风险和人工接管事项 |
| 将 `pos="0"` 行算为持仓 | 判断记录存在而非实际数值 | Decimal 检查非零持仓，挂单另查 |
| 手工拼地址、依赖长对话记忆 | 地址、时间及状态容易混淆 | 地址读注册表，状态读外部事实，报告注明核验时间 |
| 配置／模块存在就认为安全已完成 | 独立单测不等于真实路径验收 | 区分规则已定义、代码已实现、主路径已接入、演练已通过 |

## 正确开仓与平仓流程

开仓：

1. 核验账户、链、CA、instrument、份额映射、合约乘数、精度、余额、挂单及 pending。
2. 检查两腿深度、费用、额度、滑点、报价时效、对冲可达性和退出预案。
3. 买现货前估算最小可对冲规模和步长残差，不满足敞口政策则不买。
4. 持久化组 ID、请求 ID，再执行已授权现货操作；approve 只是中间步骤。
5. receipt 成功并核验实际净到账后，重算合约量、价格和风控，再提交对冲。
6. 查询真实成交、剩余订单、余额和持仓；残差满足组级验收才标记完成。

平仓：

1. 查两腿实际持仓、挂单、pending，确定本组库存，不动无关资产。
2. 正常退出优先处理流动性差的现货，按实际卖出量减少对应合约空头；合约采用适用的只减仓保护，防止反向开仓。
3. 合约已为零但现货仍在，是异常遗留敞口；按授权范围处置，不能称为正常对冲仓位。
4. 单腿失败或未知，不盲目推进另一腿；记录敞口，执行预设保护或人工接管。
5. 链上 receipt／余额、CEX 订单／成交／持仓与 SQLite 账本对齐后才标记 `CLOSED`；尘埃余额也须显式报告。

**待明确的政策冲突**：最大未对冲量为零，而非原子双腿必然有中间敞口。必须区分“在途暴露”和“最终残差”，明确前者数量、时间和保护上限；未明确前不能自动开新组，也不能自行放宽参数。

## 网络及兜底

- 已记录路线：HTTP `127.0.0.1:4780` → SOCKS `127.0.0.1:4781` → direct。使用前检测，不承诺网络永不失败。
- 读取有限重试和切换，约束次数及总时间；写请求持久化 ID 后发送，超时／响应丢失只按原 ID、txHash、nonce 查询，不换线路重复下单或签名。
- 取消失败不等于已撤销，必须继续计入可能成交的风险。
- kill switch 禁止新开仓，不会自动消除持仓，也无法撤回已广播交易。
- 全 API 不可用时保留账本和未知风险，通知人工走独立网络／设备；保护性动作仍受授权及硬风控约束。
- 恢复先做三方对账，有未解释差异、未知状态或 pending 不恢复自动交易。

## 参数与权限

- 交易计算使用 Decimal、本地数据，不调用 LLM；重试、数量、白名单、TTL 等由代码决定。
- 本地 FX 必须带来源、采集时间及有效性。历史 `7.8000` 不能仅因已入库就当成实时市场汇率；来源未核实则标记假设，不用于真实准入。
- 300 秒 TTL 是本地最大期限，不延长服务端更短期限，也不能覆盖 stale、价格变化或 simulation 失败。
- 每腿 100 USD 是上限而非目标，也不解除每日额度、余额、合约张数和裸腿约束。
- 监控白名单不等于已审核交易映射，价格 API 可读不证明 wrapper/share 比例正确。
- TEE 保管私钥不等于调用权限安全；会话权限、有限 spender 授权、额度与撤销机制仍须独立控制。
- 本复盘不是新交易或长期自动交易授权。

## 防回归验收清单

下表是验收要求，不代表本次已经测试通过；必须覆盖真实开仓、退出和恢复入口，而不只是辅助模块。

| ID | 场景 | 必须结果 |
|---|---|---|
| L-01 | 合约不存在／映射未知 | 两腿不提交 |
| L-02 | approve 成功，swap 失败／未知 | 不提交合约，恢复查询 |
| L-03 | receipt 成功但币种错误／到账为零 | 不对冲，告警 |
| L-04 | 数量不是合约步长整数倍 | 显示残差，超政策不标记已对冲 |
| L-05 | 全平仅一腿成功 | 不得 CLOSED，报告另一腿及风险 |
| L-06 | 下单响应丢失／取消未知 | 无重复写，按原 ID 恢复 |
| L-07 | pending／revert／receipt 查询失败 | 区分事实，不伪记成交、不重播 |
| L-08 | 重启／数据库不可写／三方差异 | 先恢复对账，禁止新组 |
| L-09 | 全 API 不可用／kill switch | 停新单，不把风险归零，人工接管信息完整 |
| L-10 | 旧账户快照／FX 过期／quote 提前失效 | 不作为有效数据执行 |

## 完成报告标准

每次报告必须包含：请求范围、实际动作、两腿状态及核验时间、实际成交与剩余量、净敞口与未知风险、订单／交易证据、对账结果、未完成原因和下一步。

禁止只凭一条腿成功就说“全部完成”，也禁止只凭停止发单就说“没有风险”。
# 2026-09-21 复核补充：双腿完成与平仓可用性

- `perp_closed` 只证明 CEX 空头已买回，不证明链上 token 已卖出。自动资金费/基差
  退出必须继续做钱包余额核对；确认永续为零后，spot-only recovery 不再等待基差
  目标，也不读取无关的 CEX ticker。两腿都为零且挂单读取成功，才写入
  `reconciled_flat` 终态。
- 平仓前无法读取挂单时，不能把 `None` 传进风控来绕过 `pending_orders` 检查；必须
  返回 `pending_orders_unreadable`，不发新单。真实订单 client id 或钱包广播已经
  发生而后续异常时，才写 `AUTO_HALT`；没有任何写入时只告警并允许下一轮重试。
- 监控的 issuer discovery、链上成交扫描、池状态及 gas receipt 观察都属于可降级的
  证据任务，不得阻塞 60 秒行情主循环；每类任务单线程、同一时刻仅一项在飞，未完成
  只记录 `in_flight_not_sampled`/`unknown`，不得把旧结果伪装成新鲜价格。
