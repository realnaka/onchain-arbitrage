- 6/6 笔都是 `execType=T`（taker），没有一笔按 maker 计费；

不做“精确等于 4.5”的乐观假设。

## 3. Gas：实测 0，但不写进成本模型

X Layer 回执 `effectiveGasPrice=0`、`l1Fee=0`，`gasUsed` 只是执行消耗量。
买入、卖出、approve 三种交易都是 0 费用，属于当前链/路由的赞助行为。

模型里**不**减 gas（`roundtrip_gas_budget_usdt` 保持未设置），因为这是当前
状态而不是合同承诺；一旦赞助停止，gas 会立刻变成真实成本。

## 4. 滑点：报价=成交（0 bps），但样本太小

19:05:56 那笔的价格在报价阶段就给出 1.170314949169009549 wXIAOx，回执实际到账
也是 1.170314949169009549，**相对报价 0 bps 滑点**；OKX 自动滑点上限 0.8%
（`amountOutMinimum`）留了保护。

但：

- 名义仅 4 USDT，池深 30 万 USD，占池 0.0013%，本来就不可能滑；
- 没有成交在中途被打断/部分成交的记录；
- 平仓方向完全没有实测。

因此 `slippage_bps = "5"` 与 `failure_bps = "5"` **保持不变**：它们是针对
“下次不是这么小的单”的缓冲，不是对本次实测的复述。

### 7.4 结论：`[costs] verified = true`

```toml

```

依据：永续 10 笔全 taker 全 4.5 bps；链上两侧与同时刻池价比较偏差 ±1 bps 内；
往返实测与模型相差 0.3–1.8 bps；gas 全程 0 且由 `gas_watch` 持续复核。

### 7.5 实盘往返逼出来的 7 个缺陷（都已修复并加测试）

1. **平仓不校验对冲腿是否买回**：IOC 未成交时仍卖出现货并记 `closed` → 留下**裸空 3 张**
   （真实的钱、真实的风险）。现在买回未满就中止，现货腿不发。
2. **OKX `code=1 "All operations failed"` 但订单其实已成交**：旧代码据此认为未发出，
   导致平仓只做了一半。现在任何可疑写响应都用 `clOrdId` 回查，只有确认不存在才算失败。
3. **卖出腿解码错 token**：把「支付币」当成「卖出的代币」，记成 `1.02e-11 股 @ 1e12 USD`。
   现在按方向选择被观测的 token。
4. **报价 TTL 从请求开始计时**：CLI 慢调用（>10s）返回的报价立刻算过期，平仓被拒。
   改为从**收到**报价起算（venue 在调用期间定价）。
5. **平仓计划去算了一笔买入**：用的是已经花掉的 USDG 余额，导致合法平仓被拒。
   新增 `build_close_plan()`，只算退出两腿。支持逐腿平仓（`--token-quantity 0`）。
6. **平仓还去读持仓数**（只为开仓风控服务），读失败就把平仓打断。现在平仓不读。
7. **定价探针问超过钱包余额的金额** → venue 返回“需要充值”而不是报价。
   现在探针上限 = min(预算, 可用余额×0.999)。

另外确认：**OKX 的 exact-out 在本路由不可用**（1/2/3 股、USDG 与 USDC 两个入口、
0.8%/2%/5% 滑点全部 `Min return not reached`），整股对冲改为**搜索 exact-in 金额**
（目标落在 `[N, N+5bps)`），实测残差 2.5 bps。

## 8. 2026-09-16：maker-first 实测（策略已按操作者指令反转）

### 8.1 为什么改

永续合约的盘口价差是往返成本里最大的一项，而它由 **tick size ÷ 价格** 决定：
SHEIN-USDT-SWAP tick=0.01 / 价格 4.8 → 单边 21 bps；XIAOMI tick=0.001 / 价格 3.35 →
单边 3 bps，盘口拉开时 16 tick ≈ 48 bps。做 taker 等于每次往返把这条价差付两遍。

改成：**合约先在卖一挂 post-only 单，成交后再买现货**。赚价差 + 用 maker 费率。

### 8.2 实测（2026-09-16 10:31，XIAOMI，3 张 / 3 股）

| 腿 | 结果 | 费率 |
|---|---|---|
| 合约开仓（maker，挂 3.352 = 当时卖一） | 挂 4.4 秒成交，`execType=M` | **1.60 bps** |
| 链上买入 3 股 | 10.044363 USDG → 3.000584093312683082 股 | 池费含在价内 |
| 合约平仓（taker 买回 3 @ 3.353） | 立即成交 | 4.50 bps |
| 链上卖出 3 股 | → 10.032909 USDG | — |

**往返合计 20.3 bps**（USDG −0.011266、USDT −0.00913551），拆开：

```text
合约手续费（1.6 maker + 4.5 taker）  = 6.1 bps
现货价差（买 Ask / 卖 Bid）          = 11.2 bps
合约价格变动（3.352 → 3.353，市况）  =  3.0 bps
```

与 taker 双腿的结构性对比（同为 XIAOMI、同一盘口形态）：

| 项 | taker 双腿 | maker 开仓 + taker 平仓 |
|---|---|---|
| 合约开仓费率 | 4.5 bps | **1.6 bps** |
| 合约开仓价格 | 打在买一 | **挂在卖一（+6 bps）** |
| 合约平仓费率 | 4.5 bps | 4.5 bps |
| 结构成本合计 | ~26–30 bps | **~19–23 bps** |

**开仓一侧省下约 9 bps**（2.9 bps 费率 + 6 bps 价差）。平仓仍是 taker；
如果平仓也改 maker，再省约 6 bps 价差 + 2.9 bps 费率——待操作者决定。

费率表确认：VIP1 `makerU = -0.00016`（= 1.6 bps 收费，**不是返佣**）、`takerU = -0.00045`（4.5 bps）。

### 8.3 代价与新增的失败模式（全部已用代码约束）

1. **不一定成交**：同一天一笔 3 张的挂单在卖一停了 16 秒没人吃 → 撤单、不买现货、
   状态 `maker_unfilled`。要不要做，取决于愿不愿意等。
2. **裸空窗口**：成交到现货买入之间是裸空。约束：post-only 永不越价、
   硬超时、不追价、现货失败立即 taker 回补（`maker_unwind_on_spot_failure`）。
3. **价格必须在提交那一刻读**：第一次实测用计划里的价格（20 秒前）挂单，
   到达时已低于买一 → post-only 直接撤销（`cancelSource=31`，0 成交）。
   现在提交前重读盘口，并允许有界重挂（`maker_max_reprices`，每次尝试分到时间片的
   1/N，避免一次挂单吃光整个窗口）。
4. **轮询期间读失败**：一次传输抖动让整个流程中断，而订单可能还挂着。
   现在读失败会重试，仍失败则**尽力撤单 + 状态标 unknown + 不买现货**
   （`maker_unknown`，要求人工对账），绝不把"读不到"当成"没成交"。
