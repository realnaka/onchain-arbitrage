# 价格 API 与报价 API 的分层架构（2026-10-03）

来源：operator 与 DeepSeek 的调研对话（batch price API / Quote API 分工、限频、
多链替代品）。本文件把那份调研落到本仓库，并补上本机实测。

本文件只写架构，不改代码、不改配置、不改额度与停机开关。

## 一句话结论

把「报价」拆成两种语义完全不同的东西，分层使用：

| | 参考价 `reference_price` | 可执行报价 `executable_quote` |
|---|---|---|
| 取数方式 | 批量（Jupiter `price/v3` 一次 ≤50 个） | 单笔（`swap/v1/quote`，一次一个代币对+金额） |
| 成本 | 极低，可缓存 | 高，有 TTL |
| 能用来排序/报警 | 能 | 能（但没必要） |
| 能用来算利润/进账本/下下单 | **不能** | 能，且必须在下单那一刻重新取 |

调研里的三条结论和仓库现状对得上：批量价格 API 返回「最新价」不是「可成交价」；
Quote API 不能批量；两者**共享同一个限频池**。

## 现状：错位在这里

`scripts/xstocks_gap_live.py` 现在把**全部 104 只**标的都用 Quote API 刷一遍
（Jupiter 阶梯 5 档 + EVM QuoterV2），一轮 **39–85 秒**，4 路并行就把本地代理的
TLS 打超时。而真正需要可执行报价的，一次只有少数几个候选。

实测口径（`data/xstocks_gap_live.json` 与脚本头注释）：

- `lite-api.jup.ag` 2026-10-03 一次放行约 130 次 / 27 秒，然后对全部请求回 429；
- 现在锁在 **1.5 RPS**，仍偶发 429；
- 官方口径：无 key 0.5 RPS，免费 key 1 RPS，Developer（$25/月）10 RPS / 600 RPM；
- 60 秒滑动窗口，**Price / Quote / Swap 端点共用一个池**。

## 目标：四层，各管一件事

```text
L0 目录        谁存在、精度、乘数、Kraken 状态、桥地址
               每几小时        请求量≈0（本地库 + 两个 REST）
     │
L1 扫描        全量参考价 → 排可疑          ← 便宜、批量、可缓存
               15–60 秒        每轮 ≈3 次请求
     │  只留 |基差| > 阈值 且 流动性 > 门槛
L2 确认        候选的可执行报价（1–5 档金额）← 贵、逐个、有质量标记
               跟 L1 同轮      每候选 1–5 次
     │  只有这一层的结果才算「机会」
L3 终局报价    下单前几秒，对「这一个数量」重新取一次
               每笔一次        1 次/笔
     │
L4 双腿订单与对账（已有状态机，未知一律 fail closed）
```

### 每层的数据源

| 层 | 内容 | Solana | EVM（X Layer / Ethereum / BNB / Arbitrum） |
|---|---|---|---|
| L0 | mint、decimals、multiplier、Kraken `AssetPairs`、桥地址 | xStocks/Jupiter tokens API | 桥 products + 本地 `data/xstocks_book.sqlite` |
| L1 | 参考价 | Jupiter `GET /price/v3?ids=`（≤50/次） | 链上 `slot0`/储备 + 正股价（FMP/雅虎） |
| L2 | 可执行报价 | Jupiter `GET /swap/v1/quote` | `eth_call` QuoterV2 / V4Quoter（可批） |
| L3 | 终局报价 | 同 L2，但单笔、即时、带 TTL | 同 L2 |

## 实测补充：Jupiter `price/v3` 一次给两边

2026-10-03 12:2x（本地）实测，`lite-api.jup.ag/price/v3`（不带 key）与
`api.jup.ag/price/v3`（不带 key）**都返回 200**，且对 xStocks 额外带两段字段：

| 字段 | 含义 | 例子（TSLAx） |
|---|---|---|
| `usdPrice` | 代币在 DEX 上的参考价 | 370.3777 |
| `stockData.price` | **标的股票价**（该 API 自带） | 371.43，`updatedAt` 04:16:32Z |
| `liquidity` | 该代币口径下的流动性 | 1,449,486 USD |
| `scaledUiConfig.multiplier` | 1 枚对应多少股（AAPLx） | 1.00266 |

含义：**对 Solana 那部分标的，正股对照价可以和代币价在同一次调用里拿到**，
不再受 FMP 免费档 250 次/天、每轮 12 只的限制。这两条属于本次单点实测，
要长期依赖前需再观察几个交易日（见「待确认」）。

### 同一批实测也给出了反面证据

MRNAx 同一次调用：`usdPrice` = 127.19，`stockData.price` = 189.64，
看起来是 −33% 的巨大机会；但该代币的 `liquidity` 只有 **0.47 USD**。

这就是本仓库 09-26 已经踩过的坑（GeckoTerminal 选中 1 美元池，MSTRx 报 106.95
对 159）的同一种形态。**L1 的参考价必须先过流动性/深度门槛，否则不能进候选**。

## Price V3 当预筛：实测不通过（2026-10-03 补）

operator 先用 Price V3 做预筛，结论是「不可用」。本次独立复现，数字一致，
但**口径要改一半**。原始名单取看板自己那 177 只（`load_solana()` 的口径）。

### 复现结果

| 口径 | 数字 |
|---|---|
| 名单 | 177 |
| Price V3 没有价格 | **41** |
| 能与正股对照 | **136** |
| 偏离正股 > 20% | **27**（operator 数） |

逐条核对后，27 这个数**算错了一半**，错在我们的公式：

`usdPrice` 是 **每股价**（UI 价，已经除过乘数），`usdPrice × multiplier`
才是每枚价。再除一次乘数等于扣两遍。改口径后 27 → **21**。

自证：TQQQx 乘数 2.0117，除乘数算出 −50.7%；**实时报价 162.61 USDC/枚
÷ 2.0117 = 80.83 每股，对正股 81.01 只有 −0.2%**，与看板自己的 hit 行
（−22.2 bps）一致。

### 真正的分界是流动性，不是 API 本身

用 `usdPrice` 直接比 `stockData.price`（不涉及乘数），按流动性分桶：

| 流动性区间 (USD) | 只数 | 偏离 >5% | 偏离 >20% | 中位偏离 | 最大偏离 |
|---|---|---|---|---|---|
| 0–10 | 59 | 26 | 13 | 4.24% | 16752.3% |
| 10–100 | 11 | 7 | 3 | 8.30% | 196.1% |
| 100–1,000 | 24 | 6 | 4 | 3.13% | 248.9% |
| 1,000–10,000 | 13 | 0 | 0 | 0.79% | 3.0% |
| 10,000–100,000 | 10 | 0 | 0 | 0.92% | 2.1% |
| >100,000 | 19 | 0 | 0 | 0.12% | 1.4% |

**流动性 ≥ 1,000 USD 的 42 只，没有一只偏离超过 3%。** 20 个 >20% 的离谱值
全部落在流动性 < 1,000 USD 的池子里。带乘数 ≠ 1 的高流动性标的
（AZNx ×0.511、TQQQx ×2.012、NFLXx ×10）也都在 3% 以内，反向确认了上一条口径。

### 附带的两个可用发现

1. **`stockData.price` 可以直接当正股对照价**：18 只抽样，与我们缓存的
   FMP/雅虎价**全部吻合在 ±0.2% 以内**。这能替掉 FMP 免费档 250 次/天的预算。
2. **」无价」≠「无路由」**：41 只无价里抽查 6 只，2 只（DHRx、ETNx）报价 API
   其实有路由；反向也成立，AAOIx 有价但报价返回 `TOKEN_NOT_TRADABLE`。
   所以无价清单不能直接当死名单用。

### 反向的一个疑点（待人工判断，不要自动处理）

ASTSx：Price V3 `usdPrice` = 199.96，**实时报价 199.98（两个独立来源一致）**，
`stockData.price` = 58.48，我们缓存的雅虎价 58.45。正股一侧三个来源一致，
代币一侧两个来源一致，比值 3.42。要么乘数文件缺了一次调整，要么该品种确实
长期偏离。**在人工查清之前，ASTSx 一类不进候选。**

### 对架构的影响

- **Price V3 不作为排序或候选依据**（operator 的结论成立，理由改为
  「对 70% 的标的不可信」）。
- 它保留两个用途：① `stockData.price` 当正股对照价；② 对流动性 ≥ 1,000 USD
  的那 42 只做粗排，但仍然必须过 Quote API 才算机会。
- 「41 只无价」不能当死名单；真正的死名单来自报价 API 的
  `NO_ROUTES_FOUND` / `TOKEN_NOT_TRADABLE`，按 24 小时缓存。

## 限速预算：把「每秒只发一个」写成算术

免费 key 的池子是 60 次/分钟，且 Price/Quote/Swap 共用。按 104 只标的中约
一半在 Solana 估算：

| 用途 | 每轮次数 | 轮次间隔 | 折合 RPM |
|---|---|---|---|
| L1 全量参考价（3 次批量调用） | 3 | 30 秒 | 6 |
| L2 候选报价（≤10 个 × 1 档） | 10 | 30 秒 | 20 |
| L3 终局报价预留 | — | — | 20 |
| **合计** | | | **46 / 60**，余 14 给重试 |

对比现状：一轮 104 × 阶梯 5 档 + 明细 ≈ 500 次请求且不设上限。

代价是「一轮时间」的定义变了：L1 可以 15 秒一轮，L2 只能对少数候选做。
这符合调研的结论 —— Quote API 的限频设计本来就假设你不会同时交易 100 个标的。

升级触发条件（operator 决定，不由程序自动升）：429 持续出现，或同时要跟踪的
候选 > 20 个时，改 $25/月 Developer（10 RPS / 600 RPM）。

## 必须保留的质量闸门（本仓库已有教训）

1. **流动性门槛**：`liquidity` 低于阈值的行不进候选（MRNAx 0.47 USD 那类）。
2. **报价冻结标记**：本次报价与上轮同池同价、而参考价变了 → 标「报价冻结」，
   不排第一（NBISx 235.50 那行）。
3. **数据年龄**：每行带 `checked_at` / `age_s` / `source`；参考价和成交价各自的
   年龄都要看。进程停了就显示上一轮时间 + 「已停止」，不显示空表装作没价差。
4. **费率与 hook**：费率 ≥ 50%、hook 字节码含 `ORIGIN`、或写进报价合约地址的池，
   一律不进名单（只另表列为陷阱）。
5. **不信任任何单一来源**：参考价只能触发「去看一眼」，不能触发下单。

## 多链：Solana 之外有没有同样的 API

调研只写了 Solana。映射到我们真正会碰的链：

| 链 | L1 参考价 | L2 可执行报价 | 本仓库现状 |
|---|---|---|---|
| Solana | Jupiter `price/v3` | Jupiter `swap/v1/quote` | 已有（`xstocks_requote.py` / `xstocks_gap_live.py`），走 lite-api，共享限速器每秒 0.9 次，遇 429 自动降速（13:0x 实测稳定在 0.7） |
| X Layer | 链上 `slot0` + 真实成交 VWAP | QuoterV2 `eth_call`（已实测：单次 RPC 批量 ≤10 个调用） | 已有（`xlayer_onchain.py`），另有 OnchainOS `swap quote` 通道 |
| Ethereum / Arbitrum | 同上 | Uniswap QuoterV2（与主网同一 CREATE2 地址）/ V4Quoter | 部分已有（`xstocks_v4_audit.py`） |
| BNB | 同上 | PancakeSwap QuoterV2 | 已有 |
| X Layer → Solana | 不适用 | **没有报价 API，只有桥** | Chainlink CCIP，手动，不自动化 |

关键差别：**EVM 上的「报价」是链上 `eth_call`，免费且没有 API 限频**，
只是要自己批（每请求 ≤10 次调用，公共 RPC 实测）。所以「价格 API vs 报价 API」
这个分层压力主要落在 Solana 一侧。

### 关于 Axelar

Axelar 是跨链消息网络，**本身不提供价格或报价 API**。它生态里唯一对得上
「类似 API」的是 Squid（Axelar 团队做的跨链路由），提供 route/quote 接口。

- 本次尝试联网核实 Squid 的链路覆盖失败（本地代理 TLS `SSL_ERROR_SYSCALL`），
  **标「待确认」**，没有写进任何结论。
- 我们的 xStocks 跨链走的是 **Chainlink CCIP**，不是 Axelar；
  `docs/plan.md` 明确不自动做跨链。所以这条线目前**不需要接**。

如果你要的是「其它链上有没有类似 Jupiter 的东西」：价格侧有
DexPaprika（多链、批量 ≤10）和 GeckoTerminal（本仓库已证明细池不可信）；
报价侧就是上面的链上 QuoterV2 家族，以及 0x / 1inch / Odos 这类聚合器 API
（都要 key，本仓库尚未接入）。

## 落地改动清单（待 operator 批准，本轮不动手）

1. `xstocks_gap_live.py` 拆成 `sweep_prices()`（L1，`price/v3` 批量）与
   `quote_candidates()`（L2，只对过门槛的候选做阶梯报价）。
   **注意（见上一节实测）**：L1 不能用 `usdPrice` 排序，只能取
   `stockData.price` 当正股对照价，并对流动性 < 1,000 USD 的标的直接标为
   「不可筛」。真正的省请求来自「死名单缓存」和「分批轮换」，不是价格预筛。
2. 参考价来源优先级改为：Jupiter `stockData` → FMP → 雅虎（实测三者互相吻合）。
3. 快照增加预算字段：`price_calls` / `quote_calls` / `rpm_used` / `rpm_limit` / `429`。
4. 每个候选行增加 `price_age_s` / `quote_age_s` / `frozen`。
5. 页面文案区分「参考价差」和「可成交价差」，并标出本轮是 L1 还是 L2 数据。

## 不要做的事
