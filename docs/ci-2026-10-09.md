本条记录 GitHub 仓库与 CI 的接入。**HANDOFF.md 的对应章节由当前持有它的会话补**，
本文件是给那次补充用的依据。

## 1. 现在有什么

| 件 | 位置 | 说明 |
|---|---|---|
| 远端仓库 | `github.com/your-org/arb-monitor` | **私有**。默认分支 `main` |
| CI | `.github/workflows/ci.yml` | push / PR / 手动触发 |
| 本地同口径检查 | `scripts/ci-check.sh` | 推之前自己先跑 |
| 防强推守卫 | `.githooks/pre-push` | 需 `git config core.hooksPath .githooks` |
| 自动备份（commit 后） | `.githooks/post-commit` → `scripts/auto-backup.sh` | 同上，已设 |
| 自动备份（手动/定时） | `scripts/auto-backup.sh` | 无参数，随时可跑 |

CI 的两步，与 `scripts/ci-check.sh` 完全一致：

1. `uv lock --check` —— pyproject 与 uv.lock 必须一致；
2. `PYTHONPATH=src .venv/bin/python -m unittest discover -s tests`。

两处刻意的选择：

- **固定 Python 3.14**（`uv python install 3.14`）。生产就是 3.14.4，用更老的版本
  测会放过只在 3.14 上炸的代码。
- **`uv sync --frozen`**。锁文件过期是要抓的缺陷，不是要自动修的小事。

## 4b. 自动上传：现在是什么状态

**答案：会，但触发点是「提交」，不是「保存」。**

`.githooks/post-commit` 在每次 commit 之后调用 `scripts/auto-backup.sh`，它做三件事：

1. 把当前分支已有的提交推上去（只做快进）；
2. 为这个分支打开或更新指向 `main` 的 PR（`scripts/open-pr.sh`）。**不会**把功能分支推上 `main`；
3. 把**工作区**（包括还没被任何人提交的新文件）打成一个快照，推到
   `wip-snapshot` 分支。

`main` 只由 PR 合并前进。CI 通过后 `.github/workflows/auto-merge.yml` 做 squash 合并。
这个 workflow 必须先在 `main` 上，所以把它加进来的第一笔 PR 要手工合并一次。
运行目录怎么拉 `main`，见 `docs/github-center.md`。

第 2 条是重点：2026-10-09 丢的 `capability.py`、`src/arb_monitor/data/` 都是
「文件在磁盘上但没进过任何提交」，只推提交救不了它们。实测那条分支里已经有
509 个文件（`main` 是 500 个），多出来的正是未提交的那批。

这个脚本**不碰** HEAD、真实索引和工作区：快照用临时索引（`GIT_INDEX_FILE`）构建，
所以另一个会话暂存到一半的改动不会被吃掉。它只会往远端**加**东西。

`wip-snapshot` 已在 CI 的 `branches-ignore` 里，不会刷屏 Actions。

### 为什么不是每 15 分钟自动跑

试过 launchd 定时任务（`scripts/com.arbmonitor.backup.plist`），**失败**：

```
launchd 里执行： ls ~/Documents/arb/ -> Operation not permitted
```

macOS 的 TCC 不允许 launchd agent 访问 `~/Documents`，而这个仓库在那儿。诊断用的
一次性任务已卸载，仓库里那份 plist 保留但**默认不安装**。

想真正要「保存即上传」的定时备份，只有两条路，都需要 operator 决定：

| 路 | 做法 | 代价 |
|---|---|---|
| A | 系统设置 → 隐私与安全性 → 完全磁盘访问权限，把 `/bin/zsh` 加进去 | 权限给得很宽；之后 `launchctl bootstrap` 那份 plist 即可 |
| B | 用 Codex 的定时自动化（automation）来跑这个脚本 | 每次运行消耗模型额度；好处是不需要额外授权 |

不装任何东西时的兜底：随时手动跑 `scripts/auto-backup.sh`，或
`git -C ~/Documents/arb log --oneline origin/wip-snapshot -1` 看最后一次快照。
